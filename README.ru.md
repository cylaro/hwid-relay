**Подключайте сколько угодно устройств при лимите HWID (Remnawave и совместимые панели) — все они будут считаться одним устройством.**

Самостоятельно размещаемый релей на Cloudflare Workers. Приложения подписываются на воркер; воркер запрашивает настоящую подписку с одним фиксированным идентификатором устройства (`x-hwid`, `User-Agent`, `x-device-os`, `x-ver-os`, `x-device-model`). Панель видит ровно **одно устройство** — сколько бы телефонов, ПК или телевизоров вы ни подключили.

Работает со стоковыми приложениями — Happ, v2RayTun, Streisand, Karing и любыми другими, загружающими подписку по URL. Без правок приложений и ручных полей HWID.

## Почему это нужно

Панели вроде [Remnawave](https://docs.rw/features/hwid-device-limit) считают уникальные значения заголовка `x-hwid` на пользователя. Каждая установка приложения генерирует своё значение — десять телефонов превращаются в десять устройств и упираются в лимит. Значение формирует клиент, и стоковые приложения не позволяют его менять — поэтому меняем **точку подключения**:

```
Телефон 1 (Happ) ─┐
Телефон 2 (Happ) ─┤   https://your-worker.workers.dev/<secret>/s/<token>
Телефон N      ─┘            │
                             ▼  фиксированная идентичность: один x-hwid, один User-Agent
                    Cloudflare Worker (ваш)
                             │
                             ▼
                    Панель  ──>  видит ровно ОДНО устройство
```

## Настройка (5 минут, бесплатно)

1. **Деплой** — кнопка выше (или `npx wrangler deploy`), вход в Cloudflare. Бесплатного плана достаточно (100 000 запросов/день).
2. **Конфигурация** — Worker → Settings → Variables and Secrets:

   | Переменная | Пример | Обязательна |
   |---|---|---|
   | `PANEL_BASE` | `https://panel-provider.com/sub` | да (https, без токена) |
   | `HWID` | `UE42LJXu4DbiCaBv` | да (10–64 символа `A-Z a-z 0-9 = -`) |
   | `USER_AGENT` | `Happ/1.16.0 (iOS 18.3; iPhone 14 Pro)` | да |
   | `SECRET_PREFIX` | `my-secret-1` | да (8+ символов, случайный) |
   | `DEVICE_OS` / `VER_OS` / `DEVICE_MODEL` | `iOS` / `18.3` / `iPhone 14 Pro` | опционально |

3. **Проверка** — откройте `https://your-worker.workers.dev/<SECRET_PREFIX>/health` → `{"status":"ok"}`.
4. **Подключение устройств** — добавьте `https://your-worker.workers.dev/<SECRET_PREFIX>/s/<ваш-токен-подписки>` в каждое приложение. Все они будут считаться одним устройством.

Перед деплоем идентичность можно проверить против вашей панели через вкладку Request проекта [happ-decryptor](https://github.com/cylaro/happ-decryptor): отправьте URL панели с теми же заголовками и убедитесь, что контент приходит, а `x-hwid-max-devices-reached` не установлен.

## Как это работает

Воркер — простая и безопасная труба: принимает только `GET /<secret>/s/<token>`, подменяет заголовки идентичности на ваши фиксированные значения и возвращает ответ с единственного настроенного `PANEL_BASE`. Его нельзя обмануть и заставить скачать произвольный URL (upstream не задаётся клиентом), из ответа удаляются cookie и внутренние заголовки, а приложениям передаётся только нужное: content-type, `subscription-userinfo` (трафик), метаданные профиля и заголовки обратной связи `x-hwid-*`.

Токен подписки остаётся в ссылке на устройстве; адрес панели не покидает конфигурацию воркера.

## Честные ограничения

- Панель видит одно устройство, запросы которого приходят с IP-адресов Cloudflare с высокой частотой. Провайдер может заметить это в логах сервера; использование против условий тарифа — ваше решение.
- Если провайдер блокирует IP дата-центров, релей перестанет работать — это главная негарантия, и зависит она только от вашего провайдера.
- Если провайдер сменит адрес панели или токен — обновите `PANEL_BASE` или ссылки на устройствах.
- Один воркер = одна панель + одна идентичность. Для нескольких панелей нужны отдельные деплои.
